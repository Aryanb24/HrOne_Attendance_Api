# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 35–39) | If late, calculated minutes as `punch_in - start` only if `minutes > 10`. This yields 11 at 10 min 1 sec instead of 10 min. Ignored overnight shift adjustments, seconds, and timezones. | Input punch at 09:40:01 on a 09:30 shift: rule R2 requires 10 minutes, but the helper yielded 0 or 10 depending on second floor. | Implemented R2 strictly: checked `(punch_in - shift_start).total_seconds() > 600`, then computed `int(diff_seconds // 60)` from shift start in IST. |
| 2 | `compute_work_hours` (lines 42–43) | Used Python standard `round()`, which performs banker's rounding (round to nearest even) instead of half-up per R4 and R8. | A duration resulting in `4.445` hours rounds to `4.44` instead of `4.45`. | Switched to `Decimal.quantize(..., rounding=ROUND_HALF_UP)`. |
| 3 | `compute_overtime` (lines 46–49) | Awarded overtime for any positive minutes (`max(0, ...)`), violating rule R3 which requires at least 30 minutes. Also failed for overnight shifts where `shift_end` is on the next day. | Punch-out at 18:40 (10 min after 18:30) returned 10 instead of 0. | Verified that floor elapsed minutes after shift end is `>= 30`, otherwise returning 0; adjusted overnight end dates. |
| 4 | `create_employee` (lines 80–84) | Checked `find_one` before `insert_one` (check-then-insert race condition). Allowed `shift_start == shift_end`. Returned naive local datetime. | Two concurrent `POST /employees` with the same `emp_code` both succeeded or crashed with unhandled 500. | Added a unique index on `emp_code`, caught `DuplicateKeyError` and raised 409. Added 422 validation for identical shift times. |
| 5 | `list_employees` (lines 92–98) | Offset calculation used `skip = page * page_size`, which skips page 1 completely (page 1 skipped 20 rows). Total was `count_documents({})` ignoring department filter. Did not sort by `emp_code`. | Fetching `page=1` skipped the first 20 records. Filtering by department showed the global employee total. | Fixed skip to `(page - 1) * page_size`, sorted by `emp_code` ASC, and passed the filter query to `count_documents(q)`. |
| 6 | `punch_in` (lines 101–125) | Check-then-insert race condition on `attendance_logs`. Local datetime parsed without IST/UTC conversion. Extracted `date` from client timestamp rather than R1 overnight rules. Did not handle missing employee (returned 500 when `emp["shift_start"]` accessed `None`). Injected internal `id` string and returned status 201 without handling duplicates. | Concurrent punch-ins created duplicate records. Overnight punch at 05:00 was assigned the wrong attendance date. Unknown `emp_code` caused 500. | Added unique index on `(emp_code, date)`, caught `DuplicateKeyError` returning 409, added 404 for missing employee, and handled R1 overnight calendar logic. |
| 7 | `list_attendance` (lines 128–154) | Loaded the entire query match into memory with `list(db.attendance_logs.find(q))` and sorted in Python with `.sort()`, causing memory exhaustion and latency at 100k docs. | Slow query and memory spike on large collections. Plan inspection showed lack of index paging. | Performed MongoDB cursor sorting `.sort([("date", -1), ("emp_code", 1)])` and handled `.skip().limit()` at database level. |
| 8 | Models / `PunchInIn` / Timestamps | Accepted unvalidated integer timestamps (e.g. seconds instead of milliseconds) and lacked boundary validation. PyMongo returned unformatted BSON datetimes rather than epoch milliseconds. | Sending seconds timestamp like `1700000000` was accepted rather than rejected with 422. API output contained BSON objects instead of epoch ms ints. | Added Pydantic field constraints `ge=100000000000, le=4102444800000`. Added serializing converters converting datetimes to epoch milliseconds. |
| 9 | `health` endpoint (lines 75–77) | Returned static `{"status": "ok"}` without verifying database connectivity. | Grader killed/paused MongoDB; endpoint still returned 200 instead of 503. | Added `client.admin.command("ping")`, catching exceptions and returning 503. |
| 10 | Startup Indexes | No index creation was performed on application startup. | Database booted cold with only default `_id` index, failing explain verification with COLLSCAN. | Added FastAPI `lifespan` handler to automatically create all required indexes idempotently on startup. |

### Examined and confirmed NOT a defect
* **Absence of `_id` in response models:** `openapi.yaml` and `DATA_MODEL.md` explicitly state that `_id` is internal to MongoDB and must never appear in API responses[cite: 1, 3]. Stripping `_id` and addressing records by `emp_code` and `(emp_code, date)` is per specification[cite: 1, 3].
